## User Interface Design: Principles, Process, and Standards

User interface (UI) design is the discipline of designing interfaces for machines and software with the goal of maximizing usability and user experience. It encompasses information architecture, visual design, and interaction design, and is driven by user-centered design practices — typically executed through the design thinking framework (EDIPT). The field is governed by international standards, particularly ISO 9241, which defines ergonomic requirements for dialogue and presentation.

## Key Concepts

- **UI design** focuses on *how the interface looks and behaves*; **UX design** encompasses the *entire experience*, including content, performance, and underlying systems
- Don Norman and Jakob Nielsen's distinction: a perfect UI still yields poor UX if the underlying system doesn't meet user needs (e.g., a beautiful movie search over an incomplete database)
- **Three types of user interfaces**: graphical (GUI), voice-controlled, and gesture-based (3D/VR)
- **Usability** is defined by ISO 9241 as three quality factors: effectiveness (goal achievement), efficiency (resources expended), and satisfaction (user acceptance)
- Graphic design and typography support usability — aesthetics can enhance *or* detract from functional use (Norman: "attractive things work better")
- The IFIP user interface reference model defines four dimensions: input/output (look), dialogue (feel), technical/functional (tool access), and organizational (collaboration support)

## Commands and Syntax

No CLI commands. The primary process framework is **EDIPT (Design Thinking)**:

1. **Empathize** — Conduct user research (semi-structured interviews) to understand needs, workflows, technical literacy, and aesthetic preferences
2. **Define** — Craft a one-sentence problem statement: user + specific need + desired outcome
3. **Ideate** — Brainstorm solutions aligned with feasibility, viability, and desirability
4. **Prototype** — Build solutions at varying fidelity (low/mid/high); explore multiple designs, don't settle on the first
5. **Test** — Present prototypes to target users; iterate back to earlier stages as needed

The framework is **non-linear** — designers jump between stages. Iteration is expected.

## Relationships

- **ISO 9241** is the governing standard, with Part 10 (dialogue principles), Part 11 (usability definition), Part 12 (presentation attributes), and Part 13 (user guidance)
- **Information architecture** is a foundational sub-discipline of UI design — organizing what's important
- **Interaction design** and **experience design** are sibling disciplines within the broader UX field
- **Usability testing** (think-aloud protocol, cognitive walkthrough, heuristic evaluation, pluralistic walkthrough) feeds back into the design process
- **Human-computer interaction (HCI)** is the academic research field that underpins UI design practice
- **Nielsen's 10 Usability Heuristics** are the most widely referenced evaluation framework

## Exam-Relevant Points

- **Seven ISO 9241 dialogue principles**: suitability for the task, self-descriptiveness, controllability, conformity with user expectations, error tolerance, suitability for individualization, suitability for learning
- **Seven ISO 9241 presentation attributes**: clarity, discriminability, conciseness, consistency, detectability, legibility, comprehensibility
- **Five means of user guidance** (Part 13): prompts, feedback, status information, error management, on-line help
- **Usability = effectiveness + efficiency + satisfaction** (ISO 9241 Part 11)
- **Usability inspection vs. usability testing**: inspection is cheaper, can evaluate prototypes/specs early; testing uses actual users (often with think-aloud protocol)
- **EDIPT is non-linear** — designers may revisit any stage; iteration is fundamental
- **UI vs. UX distinction**: UI is a subset of UX; great UI does not guarantee great UX
- **Design thinking framework** was formalized in 2004 by David M. Kelley at Stanford's d.school (Hasso Plattner Institute of Design)
