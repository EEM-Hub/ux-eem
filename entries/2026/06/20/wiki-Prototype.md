## Prototyping: Types, Fidelity Levels, and Design Applications

A prototype is an early sample, model, or release of a product built to test a concept or process. In UX and software design, prototyping is the step between formalizing an idea and evaluating it — producing specifications for a real, working system rather than a theoretical one. The term spans physical products, electronics, software, and human-computer interaction, but the core principle is consistent: build something testable before committing to full production.

## Key Concepts

- **Prototype definition**: An early sample or model used to evaluate a new design, test assumptions, and enhance precision before committing to final production.
- **Materialization**: The process of creating a prototype — sits between formalization (specification) and evaluation in design workflow models.
- **Fidelity spectrum**: Prototypes range from low-fidelity (paper sketches) to high-fidelity (functional prototypes capturing both appearance and behavior).
- **Six prototype types**:
  - **Proof-of-principle**: Verifies key functional aspects only; not full functionality.
  - **Working prototype**: Represents all or nearly all final functionality.
  - **Visual prototype**: Represents size and appearance, not function. Subset: **form study prototype** emphasizes geometry over color/texture.
  - **User experience prototype**: Enough appearance and function for user research.
  - **Functional prototype**: Captures both function and appearance, possibly at different scale or using different techniques.
  - **Paper prototype**: Printed or hand-drawn UI representation for early testing and software walkthroughs.
- **Prototype ≠ final product**: Prototypes differ in materials, processes, and verification rigor. Individual prototype costs are typically higher than production costs.
- **Prototypicality in web design**: How much a website deviates from expected norms — greater deviation from the prototype lowers user preference for the design.
- **Rapid prototyping**: Building partial implementations to test the riskiest parts first, avoiding the cost of repeatedly building full designs.

## Commands and Syntax

Not applicable (conceptual topic). However, related tooling and methods include:

- **Paper prototyping**: Cut paper/cardboard to demonstrate interfaces without digital tools.
- **Software prototyping cycle**: Listen to user → build/revise mock-up → let user test → iterate.
- **Alpha → Beta progression**: Alpha = first functional version with core features; Beta = most features integrated, undergoing broader testing.
- **Application Simulation Software**: Tools that simulate applications before development begins.

## Relationships

- **Minimum Viable Product (MVP)**: Related but distinct — an MVP is a shippable product with minimum features; a prototype is a test artifact that may not ship.
- **Rapid prototyping / Rapid Application Development**: Techniques for building partial prototypes quickly to reduce risk.
- **Iterative design / Extreme programming**: Gradually adding features to an initial prototype through cycles.
- **User research**: UX prototypes exist specifically to enable user research; the prototype's fidelity should match the research question.
- **Software release cycle**: Prototypes precede alpha/beta releases in the development lifecycle.
- **Wizard of Oz testing**: HCI prototyping method where a hidden human simulates computer responses — useful for testing voice interfaces or AI-like interactions before engineering them.
- **Paper prototyping**: Has fallen out of favor in some design circles due to low fidelity and limited effectiveness in user testing.

## Exam-Relevant Points

- A **proof-of-principle prototype** tests key functions but lacks full functionality; a **working prototype** has all or nearly all functionality.
- A **visual prototype** shows size and appearance only — no functionality.
- A **user experience prototype** must have enough appearance AND function to support user research.
- **Paper prototypes** are for early-stage testing before investing in digital tools; they are losing favor due to low fidelity concerns.
- **Wizard of Oz prototyping** uses a hidden human to fake system behavior — particularly useful for voice UI and complex interaction patterns.
- **Role prototypes** investigate user need and demonstrate what role an artifact could fulfill (e.g., Jeff Hawkins carrying a block of wood while developing the Palm Pilot).
- **Prototypicality** affects user preference: websites that deviate too far from expected design norms see lowered preference scores.
- Prototypes can fail even when the production design is sound (and vice versa) due to differences in materials, processes, and fidelity.
- The iterative prototyping cycle: listen → build/revise → test with users → repeat.
- **Data prototyping** produces cleansing/transformation rules validated against real data — relevant to data migration and integration projects.
